# Consistency Check (generic)

Reviews any deliverable for alignment with the active product's approved messaging framework and positioning decisions before it ships or gets added to the portfolio.

## Instructions

### Step 1: Load context

Look for the active project's brief in `memory/projects/` — this is the source of truth. If it can't be accessed, ask the user to paste it or point to the right file.

### Step 2: Read the deliverable

It may arrive as text pasted in chat, an attached file, or a reference to a file in the project folder. Read it in full before judging anything.

### Step 3: Check the 5 fixed points

For each point, determine **OK**, needs **Attention**, or has a **Critical** issue:

| # | What to check | Alignment criterion |
|---|---|---|
| 1 | **Core message** | The deliverable's central message is consistent with the context's approved core message. Doesn't need to be verbatim, but can't contradict it or invert its emphasis. |
| 2 | **Pillar hierarchy** | The context's primary pillar is the most prominent argument. Secondary pillars appear as amplifiers, not the central message. |
| 3 | **Champion and audience** | The context's primary champion is the recipient when the deliverable is sales-oriented. Other personas don't appear as the primary champion unless the context specifies a different rule for that segment. |
| 4 | **Role of secondary differentiators** (e.g., vertical expertise, a specific mechanism) | Appears as what makes the pillars possible, not as the opening promise. Leading with "we're vertical/specialized in X" as the central sales argument is a red flag if context says the outcome should lead. |
| 5 | **Canonical numbers** | Any benchmark or impact number mentioned must match what's approved in context exactly. |

### Step 4: Check additional points by deliverable type

**Battlecard:** Does it correctly identify when the competitor comes up? Is objection handling aligned with the approved tone (consultative vs. aggressive, per context)?

**Campaign brief / email:** Is the entry pain trigger correct for the segment? Is the CTA consistent with the funnel stage?

**Case study:** Is the angle one of the approved ones in context? Are quantitative results consistent with canonical benchmarks?

**One-pager / slide:** Is the headline an outcome promise, not a feature description?

### Step 5: Issue the report

Use this exact structure:

---

## Consistency Report — [Deliverable name]

**Overall verdict:** [✅ Ready to approve / 🟡 Needs minor adjustments / 🔴 Needs revision before approval]

### Fixed checks

| Point | Status | Note |
|---|---|---|
| Core message | ✅ / 🟡 / 🔴 | [One line explaining why] |
| Pillar hierarchy | ✅ / 🟡 / 🔴 | [One line] |
| Champion and audience | ✅ / 🟡 / 🔴 | [One line] |
| Role of secondary differentiators | ✅ / 🟡 / 🔴 | [One line] |
| Canonical numbers | ✅ / 🟡 / 🔴 | [One line] |

### Additional findings

[Only if relevant. Omit this section if there's nothing.]

### Suggested corrections

[A list of concrete changes, ordered most to least critical. If the verdict is ✅, write "None — the deliverable is aligned."]

---

## Severity criteria

- 🔴 **Critical:** the deliverable actively contradicts an approved decision — e.g., leads with a secondary differentiator as the central promise, uses the wrong champion for the segment, cites numbers different from the canonical ones.
- 🟡 **Attention:** doesn't contradict, but drifts from the agreed tone or emphasis — e.g., a secondary pillar appears before the primary one, doesn't mention the segment's correct pain trigger, the headline describes features instead of outcomes.
- ✅ **OK:** the point is aligned with the approved context.

## Examples

**Example 1 — Deliverable with a critical issue**

User says: "Check this one-pager draft before I send it to the team."

Actions:
1. Load context, read the one-pager in full
2. Find the headline leads with "we're built specifically for [vertical]" instead of the outcome-based core message
3. Mark point 4 (secondary differentiators) as 🔴 Critical, point 1 (core message) as 🟡 Attention since the outcome is present but buried
4. Issue the report with the exact headline rewrite suggested

Result: Laura gets a specific, actionable fix rather than a vague "tone could improve" note.

**Example 2 — Clean deliverable**

User says: "Does this campaign brief look right?"

Actions:
1. Load context, read the brief
2. All 5 fixed points check out, additional campaign-specific checks (pain trigger, CTA/funnel stage) also align
3. Issue the report with ✅ on every row and "None — the deliverable is aligned" under corrections

Result: a fast, confident green light with no invented issues to justify the check.

## Troubleshooting

**Issue: The deliverable type doesn't match any of the four in Step 4**
Cause: an unusual format (e.g., a video script, an internal FAQ).
Solution: run the 5 fixed checks regardless — they apply to any deliverable — and skip the type-specific checks rather than forcing a mismatched checklist.

**Issue: Context doesn't specify a rule for something the deliverable does (e.g., no stated rule about which persona can be a champion in a given segment)**
Cause: the messaging framework has a gap.
Solution: don't mark it Critical or Attention on a guessed rule — note it as a gap in context under Additional Findings and suggest it get resolved and documented.

**Issue: Two consistency checks on the same deliverable give different verdicts**
Cause: context was updated between checks, or the deliverable changed.
Solution: state explicitly what changed since the last check (either the deliverable or the context) so Laura understands why the verdict moved.
